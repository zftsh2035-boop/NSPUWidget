# NSPUWidget v2.1 — оптимизация и переработка компактного виджета

## Что изменилось

### 1. Производительность и R8
- **Включена R8-оптимизация Java/Kotlin-байткода** для устанавливаемой debug-APK и release-варианта. R8 анализирует граф достижимости кода, удаляет неиспользуемые классы и методы, оптимизирует промежуточное представление и переименовывает внутренние сущности там, где это безопасно.
- **Включён `isShrinkResources = true`**: сборщик ищет неиспользуемые ресурсы приложения (например, лишние XML и изображения) и не включает их в итоговый APK, если они не нужны. Это выполняется после анализа кода; фактическое уменьшение зависит от состава проекта.
- **Подключён стандартный `proguard-android-optimize.txt`** и минимальный `proguard-rules.pro`. Не введено широкое правило `-keep ru.nspu.schedule.**`, которое лишило бы R8 большей части эффекта. AndroidX, Compose, WorkManager и Jsoup используют свои правила совместимости и стандартные настройки Gradle.
- **Производительность не связываем с заменой Kotlin на Java или C++**: нативные Kotlin/Compose и системный Android-виджет сохранены. Работу ускоряем устранением лишних операций, а не полным переписыванием приложения.

### 2. Работа Compose и плавность
- **Убрана полная повторная проверка данных каждые 15 секунд.** Раньше один таймер постоянно инициировал перерасчёт всего экрана, даже когда данные не менялись.
- **Экран теперь реагирует на изменения локального расписания через listener SharedPreferences**: обновление сайта, переключение группы/подгруппы, даты, состояния объявлений и истории изменений вызывает обновление данных без постоянного опроса.
- **Локальный обратный отсчёт выбранной пары обновляется только раз в минуту и только пока приложение активно.** Остальные карточки не обязаны пересчитываться ради этого таймера.
- **Смена выделения текущей и следующей пары** инициирует отдельную проверку по границе начала или окончания занятий. Плавная пульсация сохранена; она касается только выделенной карточки и прекращается при закрытии экрана.
- **Результаты вычислений для списка уроков, временной шкалы, объявлений и группы мемоизированы в Compose** по ключам фактического обновления данных. Это уменьшает количество повторных фильтраций и построений списка.

### 3. Кэширование расписания
- **Добавлен кэш уже разобранных уроков, объявлений и истории изменений в оперативной памяти.** При повторных обращениях один и тот же JSON не парсится заново.
- **Кэш инвалидируется автоматически, когда меняется сохранённая строка JSON.** Это касается новой загрузки сайта, смены группы, скрытия/прочтения объявлений и изменений расписания.
- **Подгруппы иностранного языка вычисляются из закэшированных уроков**, а не из повторно созданного полного списка на каждом обращении.
- **Фоновое обновление через WorkManager по-прежнему запланировано примерно раз в 3 часа**, с требованием подключения к сети. Постоянная работающая служба для синхронизации не добавлялась.

### 4. Маленький виджет «Ближайшая пара»
- **Полностью перестроена компоновка компактного виджета.** Вместо горизонтального ряда, в котором время, тип и аудитория вытесняли друг друга, используются компактная шапка и вертикальные строки.
- **Два адаптивных макета по доступной площади.** Для более низкого или узкого виджета выбирается плотный вариант с меньшими отступами и типографикой. Это снижает вероятность наложений у разных лаунчеров Android.
- **Все длинные поля ограничены по числу строк и обрезаются многоточием**: особенно название предмета, преподаватель и кабинет. Короткий тип занятия (`л.`, `п.з.`, `л.з.`, `зач.`, `экз.`) остаётся в выделенной метке.
- **Нажатие на любую область компактного виджета открывает приложение**, а не только отдельные строки заголовка и предмета.
- **Системный виджет остаётся на RemoteViews**, без постоянно работающей анимации и без пробуждения процессора ради пульсации.

### 5. APK, сборка и подпись
- **GitHub Actions запускает автоматические тесты, R8-сборку и проверку целостности APK.** Размер оптимизированной debug-APK сравнивается с опубликованной версией v2.0.
- **Дополнительно собирается release-вариант.** Если у владельца настроен постоянный ключ через защищённые GitHub Secrets, `stable` публикует подписанную release-APK. Если ключа нет, публикуется оптимизированная debug-APK: она устанавливается, но это ещё не полноценная постоянно подписанная release-сборка.
- **Приватный ключ и пароли не хранятся в открытом репозитории.** Для подписи предусмотрены четыре GitHub Secrets; неполный набор секретов вызывает ошибку сборки, а не выпуск потенциально неправильной APK.
- **Отдельный workflow для проверок производительности на эмуляторе Android** собирает пять замеров запуска, `dumpsys meminfo`, `dumpsys gfxinfo` и моментальный CPU snapshot. Числа из эмулятора не эквивалентны измерению автономности на реальном смартфоне.

### 6. Совместимость и ограничения
- Настройки тем, `stable/dev`, уведомлений, подгруппы и история замен сохраняются. Функции свайпов, объявлений и «окон» между парами остаются на месте.
- **Android может отказать в установке APK поверх старой версии при другой подписи**. В этом случае удаление предыдущего приложения приведёт к потере его локальных данных и настроек. Перед переустановкой учитывайте этот риск.
- **Уменьшение APK и успешная компиляция ещё не подтверждают экономию батареи**. Для выводов о расходе энергии нужны измерения на конкретном смартфоне в одинаковых условиях.

## Результаты сборки

Здесь GitHub Actions автоматически добавит измеренный размер новой APK, сравнение с v2.0 и сведения о типе подписи.
