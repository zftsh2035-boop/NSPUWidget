# NSPUWidget v2.3 — исправление Neon и независимые темы

## Что изменилось

### 1. Исправлен вылет при выборе Neon

- **Найдена и устранена конкретная причина аварийного закрытия.** В версии 2.2 значение `neon` присутствовало в списке выбора темы и в чтении настроек, но функция `AppSettings.setTheme(...)` проверяла допустимые темы по старому списку из четырёх элементов, без Neon. При нажатии выполнялось `require(...)`, выбрасывалось исключение `IllegalArgumentException`, и приложение закрывалось.
- **Введена единая проверка `isSupportedTheme(...)`**, которая используется для чтения и сохранения обеих независимых настроек. Пять разрешённых вариантов: `system`, `light`, `dark`, `amoled`, `neon`. Неизвестные значения автоматически заменяются системной темой.
- **Добавлены тесты на выбор Neon и допустимые режимы**: все варианты должны приниматься одной проверкой, а неизвестные — отклоняться. Проверяется и возможность использования разных режимов для приложения и виджета.
- **Обновление внешнего виджета больше не вызывается синхронно при сохранении темы приложения** — эта лишняя операция была потенциальным источником подвисаний интерфейса и случайных сбоев при взаимодействии с системным лаунчером.

### 2. Темы приложения и виджетов стали независимыми

- **Добавлено отдельное поле `widget_theme` в локальных настройках `SharedPreferences`.** Раньше оба интерфейса всегда брали значение из общего поля `theme`, поэтому смена приложения принудительно перекрашивала виджеты.
- **Теперь отдельно выбираются «Тема приложения» и «Тема виджета».** Например, приложение может быть Neon, а виджет — светлым; приложение — системным, а виджет — AMOLED; приложение — тёмным, а виджет — Neon.
- **Сохранён обратный совместимый ключ `theme`** для темы приложения. Выбранная ранее тема приложения не сбрасывается при установке обновления.
- **Начальная тема виджета — «Системная».** Если пользователь ещё ни разу не выбирал оформление виджетов отдельно, оно следует светлой/тёмной теме Android, а не выбранному для приложения режиму.
- **При выборе темы виджета все установленные экземпляры обновляются без переустановки.** Перестроение RemoteViews запускается вне основного UI-потока; ошибки системного лаунчера перехватываются и записываются в Android Logcat, не закрывая экран настроек.
- **Выбор темы приложения не затрагивает виджет и наоборот.** При смене системной светлой/тёмной темы Android виджеты в режиме «Системная» продолжают реагировать на системную конфигурацию.

### 3. Переработан экран «Оформление» по примеру

- **Список из пяти высоких строк с радиокнопками заменён компактными кнопками-плитками** с закруглёнными углами, тонкой обводкой и заливкой активного варианта.
- **Первая строка:** «Системная», «Светлая», «Тёмная». **Вторая строка:** «AMOLED», «Neon». Выбор в обоих блоках отображается одинаково и остаётся понятным без отдельной легенды.
- **Внутри одного раздела «Оформление» находятся два блока:** «Тема приложения» и «Тема виджета». У каждого своё выделенное значение и собственная настройка.
- **Под кнопками сохранено краткое техническое пояснение:** системная тема следует Android; Dynamic Color доступен с Android 12; AMOLED оставляет системный акцент, но делает фон полностью чёрным; Neon использует чёрный фон и кислотные цвета.
- **Материал 3 и динамическая палитра** остались в остальных частях приложения: экран оформления адаптируется к выбранной теме, но больше не занимает пространство длинным списком.

### 4. Сохранённые функции и оформление

- **Neon не изменён по задумке:** чёрная AMOLED-подложка и кислотные зелёные, розовые, жёлтые и циановые акценты. Исправляется доступность режима и возможность выбрать его без вылета.
- **Пять тем доступны отдельно для виджетов любого размера** — большой прокручиваемый, средний и компактный с одной парой. Продолжают работать обозначения `л.`, `п.з.`, `л.з.`, `зач.`, `экз.`.
- **Сохранены прошлые оптимизации:** R8, уменьшение ресурсов APK, кэширование разбора расписания, обновление текущей пары по границам занятий и отсутствие непрерывной фоновой анимации виджета.
- **История замен, объявления с кнопкой ✓, расписание и «окна» между парами** не менялись.

### 5. Тестирование и ограничения

- **GitHub Actions** запускает регрессионные unit-тесты, компилирует debug/release APK с R8 и проверяет целостность APK. Результаты конкретной сборки доступны по ссылке на Actions.
- **Автоматический эмуляторный smoke-тест** проверяет возможность установки и запуска оптимизированной APK, но не заменяет ручную проверку на разных смартфонах и лаунчерах.
- **Подпись APK:** пока не настроен постоянный ключ подписи release, в Releases продолжает публиковаться устанавливаемая оптимизированная debug-APK. Из-за временного debug-ключа GitHub Runner обновление поверх ранее установленного APK может потребовать переустановки с потерей локальных настроек.

## Результаты сборки

GitHub Actions допишет измеренный размер файла APK, SHA-256, вид подписи и коммит.

## Ветки

- `dev` — разработка и тестирование.
- `stable` — проверенные версии и публикация GitHub Releases.
- `main` — зеркало проверенного выпуска.
